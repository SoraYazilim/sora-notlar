A firewall fresh out of the box is not yet protecting anything. Most FortiGate models ship with the management IP 192.168.1.99 and an 'admin' account with a blank password — which means the real work starts after the mounting and cabling are done. The good news: performed in the right order, the base setup of a FortiGate typically takes under an hour.

Preparation pays off before you ever touch the GUI. Rack the unit, connect redundant power supplies to two separate feeds where available, and keep a console (RJ45/USB) cable within reach. Draw up an IP plan covering the WAN, LAN, DMZ, and management segments in advance, and decide on a FortiOS version before deployment: for production, a build the vendor marks as mature beats the newest feature release, and as of 2026 the 7.6 family is the current stable option.

From first login to a working policy

Connect a computer to the internal/port1 interface, take an address from the 192.168.1.x block, and open the web GUI over https. The system forces a password change on the first session — set a strong, unique admin password there. Then handle the basics: a meaningful hostname, the correct time zone with NTP synchronization, and DNS servers. Accurate time matters more than it seems, since log correlation and certificate validation depend on it. Console access, if needed, runs at 9600 baud.

Internet connectivity is configured on the WAN interface via static IP, DHCP, or PPPoE, depending on what the ISP provides; with a static IP, remember to add a default route for 0.0.0.0/0 via WAN. The first firewall policy — LAN to WAN, source and destination 'all', an allowed service, NAT enabled — is the minimum that gets internal users online. In production it should be tightened with security profiles and narrower address objects.

Hardening is the final gate before go-live: restrict admin access to trusted hosts, add two-factor authentication where possible, disable management access on the WAN interface, and switch off unused protocols such as HTTP and Telnet. Update the firmware to the recommended stable build, and export an encrypted configuration backup — no device should enter production without one.
