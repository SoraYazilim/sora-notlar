A chatbot answers questions; an agent gets things done. The difference comes down to three ingredients: tools it can call, memory that persists across turns, and a decision loop that lets the model choose its own next step. n8n packs all three into a single AI Agent node, which means you can assemble an enterprise-grade agent on a visual canvas without writing a line of code.

Under the hood, the node runs a ReAct-style function-calling loop. User input goes to the language model, the model decides which registered tool to invoke, reads the tool's output, and repeats until the goal is reached or a step limit kicks in. Provider choice stays flexible: OpenAI, Anthropic, Mistral, and Google Vertex AI on the cloud side, Ollama for fully local models on your own hardware, plus any OpenAI-compatible endpoint such as LM Studio or vLLM.

Tools, memory, and grounded answers

Tools are where an agent earns its keep. A sub-workflow wraps an entire business process, conditions, loops, and multiple API calls included, into a single callable unit; HTTP Request nodes connect CRMs, invoicing systems, and ticket queues; database nodes expose Postgres, MySQL, or MongoDB queries. Since the model picks tools by reading their descriptions, clear action-oriented names like get_customer_orders measurably outperform vague labels. On the security side, best practice is a read-only database user for tool nodes, with write access gated behind a separate approval step.

Memory nodes keep multi-turn conversations coherent, whether through a window buffer, a token buffer, or external stores backed by Redis or Postgres for setups that must survive restarts, while a Session ID keeps different users' histories apart. Add a vector store retriever such as Pinecone, Qdrant, or PGVector and the agent gains semantic search over your knowledge base, turning the setup into full retrieval-augmented generation.

The step most teams skip, and shouldn't, is evaluation. n8n's AI Evaluations feature compares agent outputs against a labeled test dataset and reports precision, recall, and F1, so you can see how the agent behaves before it faces production traffic and measure the impact of any model change. For scenarios like customer support, internal approvals, or data analysis assistants, that validation pass makes the difference between a demo and a dependable system.
